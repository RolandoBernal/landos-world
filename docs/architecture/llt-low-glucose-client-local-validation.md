15. **Initial at/above threshold:** neutral confirmation requires Save Anyway or Go Back. No persisted record exists before confirmation. Escape returns the intact new draft. Initial glucose alone cannot qualify as recovery.
16. **Payload shape:** existing top-level record contains its initial `bloodSugar`, `recordTimestamp`, nullable `mealCarbs`, optional food components and factual notes; extension is `{ version: 1, thresholdSnapshot: object|null, rechecks: [], closure: object|null, pendingRecheck: object|null }`. Each recheck has `id`, `recordTimestamp`, `bloodSugar`, nullable `carbs`, `treatmentTimestamp`, `carbComponents`, and `notes`. Closure stores kind, confirmation time and, for recovery, a recheck reference. Reminder stores its ID, source-round ID, start and due timestamps.
17. **Version:** episode schema version 1, distinct from the existing record's optimistic-lock version.
18. **Rechecks:** embedded rounds only; saving a round updates the parent record. No episode table or top-level recheck record is created.
19. **Stable IDs:** episode identity is the existing record ID. Round IDs persist through editor/Carb Calculator rerenders and later edits. Schedule IDs distinguish superseded reminders. Duplicate round IDs are invalid.
20. **Treatment timing:** each round keeps observation/treatment timestamps together; food and treatment documentation stays on that round. Earlier-than-initial rechecks are preserved with a chronology warning and excluded from qualifying recovery. Ordering is derived from timestamps, without silently rewriting them.
21. **Derived values:** chronological latest glucose, lowest documented glucose, total recorded treatment carbs, recheck count, status and duration are computed from persisted observations. 22. **Initial save:** validate, persist locally, then queue through the existing repository, then offer optional reminder. Persistence failure keeps the draft and restores the prior in-memory document; no timer or Low Glucose queue item is started. Retrying remains a new-record save.
23. **Timer:** additive purpose support in the existing timer module/storage. Local completion uses the existing deadline chime infrastructure, once per local completion presentation. Background alarm delivery is not guaranteed or claimed.
24. **Purpose:** `low-glucose-recheck` with episode/schedule identity; existing timers default to `pre-meal`.
25. **Duration:** fixed 15 minutes, independent of pre-meal enablement/duration. No settings overwrite. Starting/replacing the single active timer requires the existing explicit conflict choice.
26. **Pending schedule:** persisted in the parent episode before starting the local timer. Local timer storage is presentation/reminder state, not clinical state. Saving a recheck or closing an episode clears its pending schedule; stopping clears the schedule without deleting the episode.
27. **Cross-device pending:** other devices display the synced due time. Only the starting device runs its local timer. Purpose-aware reconciliation suppresses schedules superseded, cleared, closed or deleted elsewhere. A stale already-completed modal cannot open a duplicate recheck. 28. **Record Recheck:** same editor and Carb Calculator, contextual treatment-carb label, no insulin controls. Parent snapshot/version checked before saving. Valid observations, dates and nonnegative recorded carbs required; malformed round insertion is rejected.
29. **Below threshold:** remains open, permits factual additional treatment documentation and optional another reminder. No prescription or automatic closure.
30. **At/above threshold:** a qualifying documented recheck exposes explicit confirmation. It does not automatically complete the episode or manufacture treatment.
31. **Explicit completion:** confirm documented recovery using a persisted qualifying recheck; confirmation is a separate deliberate action.
32. **Manual ending:** distinct confirmed action and stored outcome `ended-without-confirmed-recovery`, labeled “Ended Without Confirmed Recovery”. It never masquerades as confirmed recovery.
33. **Closure integrity:** recovery references an existing qualifying recheck at/after initial time. Editing away its eligibility clears invalid closure and reopens the episode.
